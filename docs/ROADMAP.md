# План по фазам

## Фаза 1 — инфраструктура

Подготовлены Python 3.12, фиксация зависимостей с хешами, Next.js с TypeScript и Tailwind, диагностическая страница, серверные прокси, Dockerfile, Compose с healthcheck, GitHub Actions и инструкции запуска. Проверка полного CI в GitHub остаётся отдельным шагом; успешный запуск ещё не подтверждён.

## Фаза 2 — официальный датасет и расчётный движок

Реализованы [предоставленные данные и правила](DATASET_AND_RULES.md): 5 районов, 10 показателей, 14 мероприятий, бюджет 100 и горизонт 8 кварталов. Backend проверяет пять решений, фиксированные цены, область действия, лаги, синергии и несовместимости. Контрольные значения — база **52,55768**, пример за 95 единиц — **56,54307** — закреплены тестами. API каталога, расчёта и совета используют единые схемы.

## Фаза 3 — совет экспертов

Роли урбаниста, финдиректора и условного голоса жителей адаптированы к десяти показателям и новому бюджету. Два раунда обсуждения опираются на рассчитанный результат. Демонстрационный режим и ошибки провайдера обозначены явно. Реальный запрос к модели требует ключа и доступа и ещё не проверен.

## Фаза 4 — игровой интерфейс

Добавить выбор пяти решений, района и мероприятия, контроль оставшегося бюджета и ограничений. Показывать исходные и итоговые показатели, Astana Quality of Life Score и поток обсуждения экспертов. Соединить интерфейс с API нового движка и проверить полный пользовательский сценарий.

## Фаза 5 — подготовка к демонстрации

Проверить запуск из чистой копии, задания CI и критерии хакатона. Подготовить демонстрационный сценарий и материалы для жюри.

## Идеи для развития

- Сравнение двух сценариев и визуализация изменений по районам.
- Неожиданные события и перераспределение бюджета с явно заданными учебными правилами.
- Экспорт сценария и обсуждения в Markdown или PDF, затем создание презентации.
- Версионируемые взаимодействия мероприятий и сценарии чувствительности модели.

AI не меняет расчётный движок: одинаковые данные и решения дают одинаковый Score. Реальные сроки окупаемости и реакции жителей требуют дополнительных данных и не должны выдаваться за рассчитанные факты.
